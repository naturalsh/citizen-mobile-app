# Brain

The conversation side of the voice agent: asks the questions, gives approved advice, suggests urgency and fills the report. The voice side and WhatsApp call it through three functions in [contract.py](contract.py).

## Setup

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env   # then add GEMINI_API_KEY
```

## Try it in the terminal

```bash
.venv/bin/python -m brain.cli --lang el
```

Type as the caller. `/lang tr` switches language, `/report` prints the report, `/quit` hangs up. Reports and transcripts are written to `output/` (git-ignored).

## Using it from the voice side

```python
from brain import CallInfo, start_call, turn, end_call

r = start_call(CallInfo(call_id="abc", channel="voice", phone="+30...", lang_guess="el"))
speak(r.reply_text)

r = turn("abc", final_transcript, lang=detected_lang)   # once per caller utterance
speak(r.reply_text)                                     # speak exactly this text
if r.action == "handoff": transfer_to_operator()
if r.action == "end": hang_up()

end_call("abc", "completed")   # always call this, also on "dropped" / "hung_up" / "handed_off"
```

- Send final transcripts only, not partial ones.
- **Faster replies on calls:** use `turn_stream()` instead of `turn()`. It yields `("start", {"action", "handoff_reason", "lang"})`, then `("text", piece)` events to speak as they arrive, then `("result", TurnResult)`. The pieces joined are what the caller hears; the result is what `turn()` would return. Advice and the handoff line come first, just like `turn()`.
- **Pre-recording:** `fixed_voice_texts(lang)` lists every line the brain says word for word on calls (greetings, hold, handoff, "please repeat", the advice texts). The voice side records them once and plays them from disk (voice/recordings.py).
- **Slow reply:** if nothing has been said after about 1.5 s, say `hold_phrase(call_id)` ("One moment, I'm noting that down.") so the caller doesn't hear silence.
- Pass `interrupted=True` to `turn` if the caller cut off the last reply.
- The brain saves reports itself; the voice side never touches them.
- If you have the caller's AML location, pass it as `CallInfo(aml={"lat": ..., "lon": ..., "accuracy_m": ...})`. It makes event grouping much more accurate.

## Privacy: masking personal details (`masking.py`)

Gemini never sees the caller's name, street address, phone number, e-mail or ID numbers. Each caller message is masked before it is sent (`"Θεμιστοκλέους 5"` → `<ADDRESS_1>`), the model answers with the placeholders, and the real values are put back before the caller hears the reply and before the report is saved. The post-call summary is masked the same way. Village and town names stay visible, because the model needs them for the `area` field.

Detection works mostly from **what was asked**, which the code knows (`steps.py`), not from how things are said: after the name question the whole answer is the name; after the street question every name in the answer is the street, except places already given (the area, the landmark) and a sentence's first word before lowercase words ("Έπιασε φωτιά…"); after the opening question ("what happened, and where?") a capitalised name after "στην", "στον", "οδό"… is a street unless it is a real town or neighbourhood in any grammatical case (`gazetteer.is_place`: "στην Ορλώφ" is masked, "στον Πειραιά" and "στο Βαθύ Σάμου" stay; a street named after a place, like Υμηττού, stays visible); after a texted list, see "By text" below; anywhere in the call, a name that is a **real street of the caller's area** (the OpenStreetMap street list, see the map check below) is masked, however it is phrased. Patterns still catch the rest: phone, ID and e-mail numbers, a street word with the name after it ("οδό Ορλώφ"), a street name with a house number ("Ορλώφ 12", "Θεμιστοκλέους 5"), and "my name is"-style phrases in each language. A name question the model asked on its own is recognised by its words (όνομα, name, adınız, nom…). **Not caught:** names said in passing ("my mother Eleni"), and a street said in passing before its area's street list is in (fetching it can take a minute or fail when the servers are busy, and a whole city like Athens has none; this is how "Ορλώφ" in a first sentence about Athens still reached the model in an eval run), since it can't be told apart from a neighbourhood the model needs to see. Speech-to-text and text-to-speech providers still hear everything; masking only protects the language-model step (see `Docs/Research/07`).

Set `BRAIN_MASKING=off` in `.env` to compare without it.

## Grouping calls about the same event (`events.py`)

Every turn, the brain suggests which event the call belongs to and sets `event_id` and `new_event_suggested` in the report. Calls group when they report the same hazard within a time window and:

| Hazard | Same place means | Window |
|---|---|---|
| earthquake | within 200 m (AML), or the same street address | 6 h |
| fire (building, vehicle, other) | within 150 m, or the same street address | 3 h |
| fire · wildfire | within 3 km, or the same `area` (village / neighbourhood) | 3 h |
| flood, storm | within 1 km, or the same `area` | 12 h |
| landslide | within 500 m, or the same `area` | 12 h |
| other (gas leak, explosion, road accident…) | within 300 m, or the same street address | 2 h |

**Hazards are a category and a kind** (`hazard_type`, `hazard_subtype`, `report.HAZARD_SUBTYPES`): earthquake (collapse, damage), fire (wildfire, building, vehicle, other), flood (building, street, vehicle, river), storm (wind, fallen_tree, power_line, lightning), landslide, other (gas_leak, explosion, road_accident, other). Added 2026-10-26: a car fire was filed as "other". Old reports' `wildfire` and `building_fire` read as fire · wildfire and fire · building (`report.hazard_of`). **Animals at risk** have their own list (`animals`: kind, count, trapped, injured), never counted as people, read back, and never a life threat on their own: a trapped cat was dropped from a test call.

Addresses are compared after removing accents, street words and punctuation and writing Greek in Latin letters, so `Οδός Θεμιστοκλέους 5` and `Themistokleous 5` match. `new_event_suggested: true` marks the call that opened an event: a new collapse or fire front, worth fast attention. Grouping never hides a call; every call keeps its own report and urgency.

Events are stored in `output/events.sqlite`, shared by the voice worker and the messaging server. The thresholds are first guesses to tune on real data.

## Safety rules in code

- **Advice is never written by the model**: it picks a topic and the brain reads the fixed text. The report's `advice_given` lists what the caller heard.
- **Never "100% sure":** `urgency.confidence` is capped at 0.95 (`report.MAX_CONFIDENCE`); the model gave 1.0 in tests, from one caller on a phone line.
- **The letters decide the language when they can** (`langs.script_language`): Greek letters, or a Turkish- or French-only letter (ı, ğ, ş…), override the language speech-to-text passed, which labelled a Turkish caller's "İzmir'deyim" and "Evim yıkıldı" as English in a test call; the advice then came in English. Only from 4 letters on: speech-to-text wrote an English caller's "uh" as "η.", and the next reply came in Greek (demo call, 2026-10-30).
- **The street comes only from the report's `street` field** (`places.the_street`), never guessed from numbers in `spoken_address`: "100. Yıl Mahallesi" (a neighbourhood in İzmir) was taken for a street with a house number and shown as "street not found". A numbered Turkish street keeps its number ("1593 Sokak").
- **Never a promise that help is coming** (`core._no_promises`): a sentence like "help is on the way", "yardım yolda" or "η βοήθεια έρχεται" is removed from the reply, and the first one becomes the fixed, true "Your report is going to the operators right away" (`phrases.json` `passed_on`, DRAFT). The model said "Biliyorum, yardım yolda" in a test call although the prompt forbids it; only an operator dispatches. Streamed replies are released a sentence at a time so each sentence is checked before it is spoken.
- **No Greek letters to a caller who isn't speaking Greek** (`translit.py`): street names come from the map in Greek letters, and the model sometimes slips in a Greek "okay" despite the prompt's rule. On an English demo call (2026-10-30) the agent said "Εντάξει, Orlov 12, Κουκάκι" and "Did you mean Ορλώφ?". Now, in English, Turkish and French calls and texts, a Greek acknowledgement becomes the caller's language ("Okay", "Tamam"; `greek_words.json`, DRAFT) and a Greek name inside a sentence is written in Latin letters by the Greek standard used on street signs (ELOT 743: Ορλώφ → Orlof, Ερμού → Ermou). A sentence wholly in Greek is left as it was: in Latin letters it would be gibberish. Reports, the dashboard and the operators' English copy keep the Greek names.
- **Reassurance, not orders:** to a scared or panicking caller the agent says it is with them and writing everything down for the rescuers, never "calm down" ("sakin olun lütfen" sounded cold in a test call) and never cheerful words like "great news".
- **Supported languages are the code's decision:** the model may not hand off as "unsupported language" while the caller speaks Greek, Turkish, English or French (`core._handoff_allowed`, also on streamed replies); a Turkish caller who mixed in English was handed to a person this way in a test call.
- **Not breathing → hand off at once** (`handoff_reason: "not_breathing"`): CPR needs a trained dispatcher.
- **Why a person took over** is saved in the report's `handoff_reason` (e.g. `not_breathing`, `caller_request`, `out_of_scope`), and the dashboard shows it.
- **Map check during the call** (`places.py`): after a turn that changes the location, the area is looked up on OpenStreetMap in the background, and if it isn't found, the street name (never the house number) and the known place names the speech-to-text is primed with. The next turn tells the model, e.g. "'Belokipos' was not found on the map … Did you mean Ampelokipoi?", and the report's `location.on_map` says whether it was found. The note names areas only, so the model still never sees a street. Street names in Latin letters usually aren't found, because OpenStreetMap stores Greek street names in Greek. When the area is found and the caller gave a street, the street is searched inside the area's box in every spelling (with and without doubled letters: a test call's "Καλλιρρόης" is "Καλλιρόης" on OpenStreetMap), and the report keeps where it was found as `location.street_matches`. In one place: the dashboard pins it. In several (street names repeat inside a city; "Καλλιρρόης, Athens" is in 6 places in greater Athens): the agent asks which neighbourhood, offering the two or three closest to the area's centre. Stretches under 2 km apart count as one place, so a long avenue is "Neos Kosmos (Filopappou, Petralona)", not three choices. Not found: the agent asks for the neighbourhood, since the street may have been misheard. **A neighbourhood the caller names picks the place** (`places._named`): when the street is in several places and the caller names one of them, in any alphabet and as heard ("Dikitirio" for Διοικητήριο), that one is taken at once. On a demo call (2026-10-30) the caller answered "Dikitirio" for Filippou 13 in Thessaloniki, but OpenStreetMap has no place called Διοικητήριο, so searching the street inside it fell back to all of Thessaloniki and the map showed the whole city. A landmark ("near the Acropolis") doesn't count as naming the neighbourhood Akropoli. Before asking, the map check uses what else the caller said (`places._narrow`): a neighbourhood named in `spoken_address` ("Ορλώφ, Κουκάκι, Αθήνα" with area "Athens" is searched again inside Κουκάκι), or a landmark next to one stretch only (within 2 km, and the others at least 3 times farther: the Acropolis picks the Koukaki Orlof, not the Glyfada one); the agent then confirms it in one question. The result goes into the report as soon as it is back (the dashboard map was a turn late), and if it finds the street in several places after the caller already said yes to the location, that yes is undone so the agent asks which. **A street that doesn't exist** (speech-to-text often writes Greek streets that aren't real): as soon as the area is known, its real street names are fetched in the background from OpenStreetMap's Overpass service (only the area's box is sent; the public server took 33 s for one neighbourhood in a test, so the list is kept 30 days in `output/places.sqlite`; up to 20 km; a whole city like Athens, 45 km on the map, timed out on the public servers, and there the agent asks the neighbourhood first anyway; three public Overpass servers are tried in turn, since one often answered 502 or 504). When the street isn't found, the one that sounds closest (in Latin letters, at least 0.75 alike; a surname alone matches the full name) is suggested: "Did you mean …?". The model sees it only as an `<ADDRESS_n>` placeholder (`Masker.hide`). A street only matches **its own name** (`places.same_street`): the same words, letters and road word aside ("Orlof" is Ορλώφ), or the same number of words spelled a little differently (Καλλιρρόης / Καλλιρόης); in Greek a caller may drop the first name ("Διάκου" for "Αθανασίου Διάκου"), elsewhere an extra word is another street, and a different road word (Cadde / Bulvar) too. A live check had matched "Kaya Sokak" to "Yuvarlak Kaya Sokak", a different street. A name's last v, w or ff counts as f (words of 4 letters or more): English speech-to-text writes "Orlov" for Ορλώφ, which is "orlof" in Latin letters, and on a demo call it took a second question to find it. When the closest real street sounds the same (0.9 or more), it is the same name in other letters, e.g. "Orlof" texted in Latin letters for Ορλώφ, which OpenStreetMap has only in Greek: it is used at once, with no question. Until the list has arrived, the agent asks the caller to repeat or spell the street, as before; once the list is in, the map check runs again on the next message (in a WhatsApp test the first fetch got a 504 and "Orlof" stayed "not found"). `BRAIN_STREET_LIST=off` turns the lists off; `OVERPASS_URL` picks a mirror. **Local index** (`osm_index.py`, since 2026-10-28): on that day overpass-api.de answered automated requests with a notice to run your own server, and both mirrors timed out, so the lists now come from a local index of every named road in Greece and Türkiye when it is built. It answers at once, sends nothing, and also covers whole cities (up to 80 km, so Athens and Piraeus get a list and "fragiadon" in Piraeus is Φραγκιάδων at once); Overpass stays the fallback. Set it up with one command, and run it again monthly: `.venv/bin/python -m brain.osm_index setup`. It installs osmium (`requirements-build.txt`) if missing, downloads `greece-latest.osm.pbf` and `turkey-latest.osm.pbf` from https://download.geofabrik.de/europe/ (342 and 652 MB in October 2026) into `output/osm/`, checks them against Geofabrik's MD5 (a copy that is already the latest isn't downloaded again), and builds the index (about 4 minutes and 2 GB of memory on a laptop). From files you already have: `.venv/bin/python -m brain.osm_index build output/osm/*.osm.pbf`. `BRAIN_LOCAL_OSM=off` goes back to the servers. **The area is a place, never the first thing named like it** (`places.area_hit`): on a demo call (2026-10-30) the model wrote the area as "Acropolis, Koukaki, Athens", OpenStreetMap's first answer was a holiday flat called "Spacious apt in Koukaki FIX 500 meter to Acropolis", and the street was searched only inside that flat, so Ορλώφ wasn't found and the dashboard pinned the flat. Now only a place counts as the area (a neighbourhood, town, island or district: OpenStreetMap's `place` and `boundary`), and if the area as said isn't one, its most local parts are dropped one by one ("Koukaki, Athens"). Whether an area counts as found still drops parts only while two are left, so a misheard "Belokipos, Athens" isn't taken as found because "Athens" is. The search cache moved to a new table, since the old one kept such answers. `BRAIN_PLACE_CHECK=off` turns the whole map check off.
- **Deaths are never dropped:** `people[].dead` counts who died; any mention of a death makes the call a life threat, and the agent asks next whether anyone there is injured, trapped or not breathing (a test call turned "5 have died and 2 babies" into "7 people, 1 injured"). A word in a sentence about people that makes no sense gets "who exactly?".
- **Misheard places and streets** (test call 2026-10-26: Παιανία heard as "Πυρανία", "Βασιλίσσης Φρειδερίκης …" as "Σφαιρική …"). Three layers, cheapest first:
  - *Every place of Greece and Türkiye* (`gazetteer.py`): 69,890 towns, villages and neighbourhoods from [GeoNames](https://www.geonames.org) (CC BY 4.0), kept in `data/places_gr_tr.tsv.gz` (1.1 MB, no network at run time). An area the map doesn't know is compared by sound with them (Greek written as said: αι = e, ου = u, μπ = b; double letters single), only within 60 km of the city the caller named, with a small lead for bigger places. "Πυρανία" now gives Παιανία; before, the 77 hand-made demo places gave Πετράλωνα. Rebuild: `.venv/bin/python -m brain.gazetteer build <folder with GR.txt and TR.txt>`.
  - *Speech-to-text hints*: the voice side gets the area's real street names from `street_hints(call_id)` once the map check has them, and adds them to Soniox's context mid-call (`voice/keywords.py`).
  - *A misheard street, asked and fixed by code* (step `confirm_street`, `core._answer_to_suggestion`): when the map has no street of the name heard but one that sounds like it, the next question is only "Did you mean <the real street>?". On a yes the code, not the model, puts the real street into the report with the house number; on a no the caller's street stays and is not questioned again; on "I don't know" or an answer about something else the caller's street also stays and the question is dropped (in the test set of 2026-11-16 it was asked three times while the caller reported a person under a tree); the street said once more, a question or one unclear word is neither, so the question is asked once more and then dropped. The suggestion is kept in `location.map_suggestion` for the operator either way. A street is never read back twice in a row or beside the one it was mistaken for (`core._tidy_streets`). From a live call on 2026-11-15: a street was heard under a wrong name every time, the model read the map's street and the heard one back together ("Φραγκιάδων Φραγγυλλιδών 16"), and the caller's "no" with the street was written with the wrong name again. Masking also missed that street: genitive endings with the accent on them ("-ών") were not listed, and a street said again without its number went to the model as plain text. Both are masked now (`masking.py`).
  - *While the map looks a street up* (`steps.py`, `street_in_message`, `map_pending`): a caller who says the street and number is not asked the neighbourhood of a whole city, nor read the location back, until the map has answered; people and injuries are asked meanwhile. If the map cannot be asked, the neighbourhood is asked as before. The read-back waits only while people and injuries are still to ask. A caller's bare goodbye ("Αντίο", "bye", "hoşça kal", "au revoir") gets the fixed line that the report is passed on, and the line stays open (`core._goodbye`). From the live call of 2026-11-15. A rule that kept the name question back until the place was confirmed was tried and removed the same day: in the test set it made the agent repeat the read-back to a caller who did not answer it, where it used to move on.
  - *Spelling, last resort* (`spelling.py`, step `spell_street`): when the street isn't on the map and the area's street list has nothing that sounds close, the agent asks the caller to spell it. Letters, Greek and Turkish letter names, "Φ όπως Φώτης" and "Φρει-δε-ρί-κης" are joined by code into one word, which goes into `location.street` and to the map check; the model sees only `<ADDRESS_n>`. Asked once. Not verified with real spelled speech: how Soniox writes spelled letters is a guess.
- **A call ends only on a clear yes** (`core.clear_yes`): if the model wants to end but the caller's last words aren't a short yes without "no" or "but" (ναι, σωστά, yes, evet, oui…), the agent says the fixed "Before I pass this on: is everything correct now?" instead, at most twice per call. Information-only calls may end without it. On streamed voice replies the goodbye is never spoken first. A test call had ended right after the caller corrected their name. A corrected name is read back; an unusual one is spelled.
- **Sounding less like a form:** most replies start with a short, varied acknowledgement ("Κατάλαβα.", "Εντάξει.").
- **Landmarks and misheard names:** the report keeps a named landmark in the caller's own words (`location.landmark`, e.g. "τζάμι ο νοσοκομείο", which is how speech-to-text heard Τζάνειο Νοσοκομείο). The map check looks it up; if it isn't found, it lists the real places of that kind in the area on OpenStreetMap ("hospitals in Piraeus") and suggests the one that sounds closest, compared after writing both in Latin letters (`location.map_suggestion`). If the caller named only a kind of place ("the hospital"), the note lists the real ones so the agent asks which. The model is told that a name which isn't a real place was misheard: it asks the caller to repeat or spell it and never guesses a real name itself (its guesses were wrong in tests, e.g. "Μεταξά" for "τζάμι ο νοσοκομείο"); only the map check's suggestion is offered as "Do you mean …?". A landmark containing a masked personal detail is never sent to the map.
- **The code runs the call's questions** (`steps.py`, [Docs/Research/09](../Docs/Research/09_Location_Questioning.md)): after every answer the brain works out the next step from the report, and a `(next: …)` note on the caller's message tells the model to ask exactly that, also listing what comes after. The order, skipping what is known: **what happened first** (callers lead with the problem, and the greeting asks "Tell me what happened, and where."; changed on 2026-10-26 after a test caller said it is how people speak: "my house burned down", then where), then area, which neighbourhood when the area is a whole city (over 12 km on the map: Athens is 45 km, Koukaki 2.8), street (or a named landmark), which neighbourhood when the map finds the street in several, **house number**, the nearest corner (`location.cross_street`) when there is no number, where exactly at a landmark; the **location read-back** (word for word; `location_confirmed` only on a yes, cleared by any later change, at most 3 tries, then the dashboard shows "⚠ location not confirmed"); how many people; anyone injured or trapped; the floor in a building fire; the caller's name; the final read-back. A step is asked up to twice (the second time in simpler words, with help for the location), or skipped at once on a clear "I don't know" (δεν ξέρω, bilmiyorum…); location pieces at most 8 times in all. The model still words each question, extracts the facts, picks advice and decides handoffs, and someone not breathing still goes to a person first. Why: when the model ran the order itself, its own labels were unreliable. In test calls it read the location back after one question, skipped the read-back, asked for a number the caller had already given, and asked for the name while labelling the question "other", so the name reached it unmasked. Now the model also names the item its reply really asks (`expecting`, by step name, or "other" for a clarification such as "who exactly?"); the code counts the caller's answer against that, falls back to its own step when the label is missing, and drops a step the model keeps ignoring after a few notes. For masking, a name question counts as one if the code scheduled it, the model labelled it, or its words ask for a name. The street is kept on its own (`location.street`) so it is searched on the map even without a number, and every detail is added to `spoken_address`, never replacing earlier ones. The answer to the opening question is masked like a location answer, since it often says where too ("it's burning at Ορλώφ 12").
- **By text there are no single questions** (`steps.form_items`, `core._add_form`). Every reply ends with one numbered list of everything still missing, in the person's language (`form_*` in `phrases.json`, DRAFT): what happened; where (town, street and number, or a landmark) in one item; how many people; anyone injured or trapped; the floor in a building fire; the name. After the person's answer, one reminder lists only what is still missing; then the final read-back ("reply YES or correct it"). What two lists didn't get is left to the operator. The model only acknowledges and confirms what a map check flags, in at most two sentences. A WhatsApp test had taken a dozen messages for one report; now it is two or three. The answer to a list is masked as a list (`Masker.mask(..., "form")`): the name after a cue or the last full-name piece, then each line like a street answer, keeping pieces that are exactly a real town or neighbourhood visible. That name goes into `caller.name` by code, since in an eval run the model saw `<PERSON_1>` and left the name empty. A word typed in any case followed by a number ("fragiadon 16") is masked as an address too, and a label after a name ("John Doe name") is dropped before the name is found. A label before it counts as a cue: "Name is John Doe", "Name: …", "Όνομα: …", "İsim: …", "Nom : …" (not "street name is"); a WhatsApp test (2026-10-31) wrote "Name is John Doe", nothing matched, and the model saw the name. **No question twice:** a floor in any of the four languages ("5th floor", "3ος όροφος", "4. kat", "2e étage"; `steps.floor_said`) counts as the floor answered, since the report has no floor field and that test was asked the floor again after giving it; and when a list follows, the model's own questions and requests for details ("Please tell me your exact address and details.", which it wrote right after getting them) are dropped from the reply (`core._no_requests`).
- **Area and street filled in by code when the model leaves them empty** (`core._area_from_address`, `core._street_from_address`). The model can't tell that a masked `<ADDRESS_1>` is a street, and once wrote "fragiadon 16 Piraeus" with no area, so the map check found nothing (WhatsApp test 2026-10-27). The area becomes the real places at the end (or start) of the address ("Κουκάκι, Αθήνα"; `gazetteer.is_place`, which never counts a name with a street word, "Gazi Caddesi", as a place). The street becomes the masked address value without its number, and is registered with the masker so the end-of-call summary masks it too. A whole city like Piraeus (45 km on OpenStreetMap) has no street list, so a street typed in Latin letters there is found only after the neighbourhood: the next list asks for it. A missed-112-call text starts with the list.
- **Unclear answers are confirmed first** (`_unclear`): a one-word answer, or one heard as a question, holds back any advice for that turn and tells the model to confirm it ("Did you say fire? What is burning?"). Speech-to-text heard «Φωτιά;» in a test call where nobody mentioned a fire, and the agent gave wildfire evacuation advice at once. A yes, or a clearer answer, releases the advice. A caller who says they are panicking gets one calming sentence before the next question.
- **One odd sentence is not a handoff:** speech that makes no sense in the conversation (often someone in the background) gets "please repeat"; only two failed tries in a row hand off.
- **Hesitation sounds** ("εε", "ıı", "ehm") before an answer to "what is your name?" are never masked as part of the name (`masking.py`). A name-like answer that shares a word with a name given earlier is masked even when nobody just asked for it, so a correction at the read-back ("Αιγέας Δοκιμάκης" for "Αγίας Δοκιμάκης") stays hidden. A first name given out of turn is still not caught.
- **English for operators:** every turn's answer also carries `caller_en` and `reply_en` (after the reply, so speech isn't delayed), saved as `text_en` on each transcript line; fixed phrases and advice use their English versions from the JSON files. The end-of-call summary request returns `summary_for_operator` (Greek or Turkish) and `summary_en` together. No extra requests; the model still only sees placeholders. Older transcripts have no `text_en`. The summary's other language, which the dashboard's "Show original" shows, is the caller's when they spoke Greek or Turkish (`BRAIN_OPERATOR_LANG=auto`), so a Turkish caller on a browser test link (Greek test number) gets a Turkish original, not Greek. Each transcript line keeps the language it was said in, and a line whose letters prove another language is never saved as its own English copy: a Turkish caller's lines, mislabelled English, once were, and the dashboard then had no "Show original (Türkçe)".
- **After the read-back:** a correction or new information goes into the report at once (situation, people, urgency) and only the change is confirmed; the full read-back is said at most twice, and a bare "no" gets "the place, what happened, or the people?".
- **Advice must match the hazard:** a fire in a building is `building_fire` (its own advice, DRAFT), never a wildfire, a fallen tree without a storm is not storm advice; no advice is better than the wrong advice.
- **Unsure if advice fits:** the agent asks the one question that settles it (inside or outside, breathing or not) and gives the advice on the next turn; it never delays when someone may not be breathing.
- **Made-up placeholders:** if the model's reply uses a placeholder we never made (it invented a name or address), the caller hears the fixed "please repeat" line instead of a sentence with a gap, and a name or address field with one is ignored. On a streamed voice reply the words before the placeholder may already have been spoken.
- **People at risk:** `people[]` counts `trapped`, `injured`, `cannot_walk` and `unresponsive` (unconscious or not breathing). The dashboard sorts life-threats by them. Unknown numbers are left out (never 0), and a group the caller can't count fully (voices under rubble) has `at_least: true`: the dashboard shows "1+ trapped" and the read-back says "at least".

## Surge mode (`control.py`)

How readily the AI hands a caller to a person. An operator switches it on the dashboard; the brain reads it on every turn (`prompts.HANDOFF_RULES`).

| | Surge (default) | Normal |
|---|---|---|
| Not breathing, unsupported language, not understood twice | person | person |
| Crime or violence happening now | person | person |
| Caller asks for a person | explains operators are with life-threats, continues; person only if they insist | person |
| Not a disaster call, nobody in danger (cat in a tree, lost item) | recorded as `information` / `needs_help` "not urgent during the disaster", caller told, call ends | person |

The default is `BRAIN_HANDOFF_MODE=surge`, because the service only runs when 112 is overloaded. A damaged switch file counts as normal: handing off more readily is the safe side. The eval runner fixes the mode per case, so the live switch never changes test results.
- **Urgency is only suggested**, always with reasons; `confirmed_by_operator` is never set by the AI.
- **Slow or busy model** (issue #4): the brain waits at most `BRAIN_MODEL_TIMEOUT_S` (4 s) for the live model, then asks the backup model (`BRAIN_BACKUP_MODEL`, `gemini-3.5-flash`, its own quota), then the live model once more; only then does it ask the caller to repeat. Gemini refuses deadlines under 10 s, so requests are sent with 15 s and the shorter waits are enforced on our side: a slow request is abandoned, and it still counts against the quota.

## Spending protection (`budget.py`)

The Gemini project has a €5 spending cap, but Google can still charge for usage inside a roughly 10-minute window before the cap takes effect. So every Gemini request (replies, backup attempts, summaries) is counted first, in `output/budget.sqlite`, shared by the voice worker, the messaging server and the eval runner.

| Setting | Default | |
|---|---|---|
| `BRAIN_MAX_REQUESTS_PER_HOUR` | 300 | about €0.50 an hour at most |
| `BRAIN_MAX_REQUESTS_PER_DAY` | 1500 | about €2.50 a day at most |
| `BRAIN_LIMIT_NOTIFY` | on | macOS notifications |

**When the limit activates you are told three ways:** a macOS notification with a sound, a `BUDGET LIMIT ACTIVE` error in the log, and the file `output/BUDGET_LIMIT_REACHED.txt` (removed when it lifts). You also get a notification at 80% of either limit, and when calls are allowed again.

While it is active the brain does not call Gemini: callers hear the normal handoff line and are handed to an operator (`handoff_reason: "budget_limit"`), summaries fall back to the English `situation`, and the eval runner stops. It lifts by itself as old requests leave the hour or day window.

```bash
.venv/bin/python -m brain.usage     # current usage
```

The euro figures are estimates from token counts and list prices (about €0.0015 per reply on Flash-Lite), not measured bills.
